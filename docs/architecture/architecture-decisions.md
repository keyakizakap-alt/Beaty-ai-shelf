# 設計判断の記録（ADR）

## ADR-001：試作版はAIのAPIを使わず、手動記録方式にする（2026-11-02）
- **状況**：ユーザーから「とりあえずAPI抜きでアプリを作成」と指示。APIキーと課金の準備前に、画面と集計の流れを検証したい。
- **決定**：利用者がChatGPT・Gemini等に自分で質問し、回答を貼り付けて記録する方式にする。AIへの自動の定期質問は「準備中」と明記し、押せない／動かないボタンは置かない。
- **理由**：中心価値（美容向けの質問、登場順の集計、競合とのギャップ、薬機法の表現確認）は、APIなしでも本当に動く形で提供できる。
- **影響**：自動計測を追加するときは、`Observation` を作る部分に計測処理を足すだけで、集計・画面はそのまま使える。

## ADR-002：データはブラウザ内（localStorage）にのみ保存する（2026-11-02）
- **決定**：サーバー・DB・認証を持たない。書き出し・読み込み・全削除の機能を用意する。
- **理由**：月額0円、個人情報を取得しない、外部送信がないため、プライバシーと法務のリスクが最小。
- **代替案**：Supabase（認証＋PostgreSQL）。複数端末・チーム共有・自動計測（定期実行）が必要になった段階で移行する。
- **制約**：端末間で共有できない。ブラウザのデータ消去で失われる（画面と規約で明示）。読み込んだデータは型と値を検証し、言及は保存値を使わず再計算する。

## ADR-003：ブランド検出と集計はLLMを使わず、決定論的に行う（2026-11-02）
- **決定**：正規化（NFKC・小文字化・ひらがな→カタカナ・記号除去）＋別名の文字列照合。英数字の別名は単語境界を確認し、重なる一致は長い方を優先。
- **理由**：同じ入力から必ず同じ結果が出る。テストで正しさを確認できる。費用ゼロ。
- **限界**：AIが別名に登録していない表記（誤記・新しい略称）を使うと検出できない。将来、LLMによる抽出を追加する場合も、この照合結果を基準に評価する。

## ADR-004：表現チェックはルールベースの一次確認とする（2026-11-02）
- **決定**：化粧品の効能の範囲（56項目、薬食発0721第1号）と静岡県「違反事例（誇大広告）」、医薬品等適正広告基準の考え方にもとづく正規表現ルール。56項目の範囲の表現（例：日やけによるシミ、ソバカスを防ぐ）は除外する。医薬部外品を選ぶと、承認効能の範囲になりうる表現は「参考」に下げる。
- **理由**：根拠を示せる。誤検出・見落としをテストで管理できる。
- **限界**：文脈判断はできない。適法性を保証しないことを画面・規約で明示し、最終判断は専門家とする。
